# Myrlet UI Design System

Visual and interaction principles for the Myrlet Web UI (`apps/web/`, React/TypeScript/Vite served same-origin by `hub`, with an optional Tauri 2 desktop shell in a later iteration). Product semantics remain owned by [the canonical architecture](../architecture/README.md).

## 1. Design Intent — Quiet Precision

Myrlet is operational infrastructure, not a chatbot or decorative SaaS dashboard.

- **Calm & precise**: restrained solid surfaces, clear labels, aligned identifiers, explicit state.
- **Truthful**: never invent percentages, step counts, running verdicts, or success/failure from `finished`, `cancelled`, or offline Workers.
- **Read-only by contract**: the Web UI observes the Hub. Creating, importing, cancelling, finishing, adding subtasks, and copy/retry are CLI operations and appear nowhere in this UI.
- **Accessible without color**: pair every semantic status color with clear text and shape, full keyboard reachability, visible focus rings, and reduced-motion support.
- **Avoid**: nested decorative cards, gradients/glows, ambient animation, hover-only critical actions, native `<select>` elements, or ad-hoc colors/spacing outside shared tokens.

### Reading workflow facts

Explain `held` with the blocking dependency IDs and statuses, and `queued` with the Slot and capability requirements. Display a Worker assignment only for a committed Delivery. Use the latest Hub Result in Task Detail, refresh it on invalidation, and remove it after a confirmed clear. A disconnected Hub leaves the last observation stale. The Web workspace remains a reader of Task data; dependency edits and submission belong to the Owner CLI.

## 2. Tokens and Shared Controls

- **Appearance**: exactly two visual themes — **light** and **dark** — selected by **System** (default, follows `prefers-color-scheme`), **Light**, or **Dark**. `hub.themeMode` resolves to `light` / `dark` and is written to `<html data-theme>`; only an explicit choice persists (`myrlet.theme`).
- **Brand**: `BrandMark` (the ant collaboration silhouette) paints with `currentColor`; `public/favicon.svg` mirrors the same path and swaps ink to `prefers-color-scheme`.
- **Fact wording**: Single formatting source for Task status (`Held`, `Queued`, `Dispatched`, `Handling ended`, `Cancelled`), Delivery milestones, and Progress provenance.
- **Spacing scale**: `4px`, `8px`, `12px`, `16px`, `24px`. Compact desktop controls `28–32px`; dense rows `28–38px`.
- **Typography**: System sans for UI, monospace only for IDs, shortcuts, and aligned numbers.
- **Motion**: `120ms` / `180ms` for state changes; instant command palette; respect `prefers-reduced-motion`. No ambient animation.
- **Storage**: only the non-sensitive appearance preference (`myrlet.theme`) and Board layout offsets (`myrlet.atlas.positions`) are persisted; **never** store bearer tokens in `localStorage`, URLs, or packaged assets (keep credentials in memory only).
- **Controls**: no native `<select>` anywhere. Segmented controls (`.mode-switch`, `.theme-segment`), pills, and buttons carry every choice.

## 3. V1 Workspace Information Architecture

V1 is a single, full-width **Work Atlas** workspace whose home view is the relationship `Board`, with a dense `List` as the alternate view, a collapsible right Inspector, and a slide-over Workers drawer, served same-origin by `hub`. There is no page navigation, no second App Bar row, and no separate Events surface — SSE frames are internal cache-invalidation hints, not a product view.

- **App bar (one 52px row)**: Brand mark plus a clickable live-connection pill (`Hub live` / `Reconnecting…` / `Connecting…` / `Disconnected`; the Hub host and SSE cursor live in its tooltip and accessible name) on the left; the centered `Board | List` segmented switch in the middle (with `List` active by default); a `Workers` online/total pill (drawer trigger) and a Settings popover on the right. The popover holds the `APPEARANCE` segment (`System | Light | Dark`, `menuitemradio` rows with `Monitor` / `Sun` / `Moon` icons), a divider, `Keyboard shortcuts (?)`, and `Disconnect`; it closes on outside click or Escape. There is no search field, Status select, Worker select, `Import`, or `+ New Task` in the chrome. **At `≤720px`** the brand wordmark and the connection wording hide (the pill keeps a dot and an explicit `aria-label`) and the switch sheds padding, so status, mode, and actions never overlap; the `Workers` pill keeps an explicit accessible name when its label collapses.
- **Task List (`List`)**: A dense, scannable outline. One sticky column header (`Task`, `Status`, `Progress`, `Worker`, `Actions`) sits above `28–34px` rows: the Task title leads and owns the flexible column, relationship micro-pills (`+n`, `deps`, `retry`) follow inline, and the state, Harness Progress, and assigned Worker align on the row's single line. Multi-node Task Groups are slim dividers, not repeated cards, and a divider shows only a subtree summary (`n subtasks · n queued · n dispatched · n ended`) with a tree glyph — never a repeated group title; independent root Tasks need no divider at all. Hover only tints the row; the desktop-only `Copy ID` action appears on hover/focus/selection and never overlaps the title. Rows are read-only; there is no `Subtask`, `Retry`, or other Task write. Truncated Snapshots (`tasksTruncated`) state `loaded of total` explicitly. **On phones (`≤820px`)** the column header disappears and the title takes the full row width (wrapping instead of truncating), `Copy ID` is absent from the row (copying lives in Task Detail), status and Worker share one compact line, the Progress line renders only when the Harness actually reported Progress, and empty Progress/Worker cells render nothing at all — no placeholder dash.
- **Work Atlas (Board — default read-only spatial canvas)**: Dot-grid canvas grouping independent root trees (`TASK GROUP`) with left-to-right tree spines (up to 5 levels) and live cubic Bézier curves for the three real Hub relationships (`parentTaskId`, sibling `dependencies`, and `sourceTaskId`). Board controls live in a real dock row above the canvas (`.atlas-dock`, a `Board controls` toolbar) with a `Relationships` label, the active-filter pill, and `Fit`, `Focus` (only with a selection), `Restore` (only when a layout can be restored), `Arrange`, and the `Inspector` toggle — so nothing covers the Task Group labels or the first card row. Selecting a Task mutes unrelated cards (`.atlas-node[data-dimmed]`: subtle border, no shadow, head/meta/footer at `0.45` opacity, edges at `0.3`) while every card title stays fully rendered and readable. Task titles lead each node. The first desktop frame uses at most 100% zoom. On narrow screens the first root is framed for reading, the minimap starts collapsed on phones, and Fit shows the whole board. Local presentation dragging, zoom LOD, and the `OVERVIEW` minimap never mutate Hub Task data or relationships.
- **Filters**: one dimension only. On desktop, clicking any of the five honest status counters in the status bar toggles `statusFilter`; List and Board both narrow to that status, and the dismissible `.active-filter-pill` (or `Esc`) clears it. **On phones** the five counters collapse into one `status-filter` trigger that names the current status and opens a `menuitemradio` menu (`All statuses` plus the five states, each with its count); choosing a state closes the menu and shows the same dismissible pill. Escape closes the menu first, then clears the filter. There is no free-text or per-Worker filter, and never a native `<select>`.
- **Inspector (full-width by default)**: The right Inspector starts **collapsed**, giving the workspace the whole width. Selecting a Task — on the Board, in the List, from `⌘K`, or from a Workspace Inspector attention row — opens the Inspector on that Task's read-only 4-tab `Task Detail` (`Overview`, `Tree & Deps`, `Delivery`, `JSON`). Clearing the selection (empty-canvas click, `×`, or Escape) retracts the Inspector. Toggling `Inspector`/`I` shows the `Workspace Inspector` (queued/dispatched attention rows, Worker counts, Manage shortcut) when nothing is selected. **Below 1024px** the panel becomes a fixed sheet above a sibling `.inspector-scrim` — never a scrim wrapping the panel — so the panel's own close button always wins the hit test; the workspace goes `inert`, focus moves into the panel, and both `Esc` and the close button restore focus to the real triggering element (the row, card, or toolbar button that was focused before opening).
- **Workers & Pairing (slide-over drawer)**: Opens from the App Bar `Workers` pill, the Workspace Inspector `Manage` shortcut, or `⌘K`. Contains one-step enrollment code generation (`worker pair` command), Slot/capability/Executor inventory (`null` capacity rendered as `—`), and credential rotate/revoke, laid over the still-mounted workspace. Escape closes the drawer before it touches Task selection.
- **⌘K Command Palette**: Task jump list, `Board` / `List`, `Workers & Pairing`, `Toggle Inspector`, `Fit Board`, `Arrange Board`, and the three appearance options. No create or import commands.
- **Status bar**: Desktop `26px` — five clickable honest status counters (`Held`, `Queued`, `Dispatched`, `Handling ended`, `Cancelled`), then Task and relationship totals, Board zoom when on the Board, and the `⌘K · I · ?` shortcuts hint. Phones `44px` — the single status filter trigger plus Snapshot totals. Live connection and Worker counts are not duplicated here — they belong to the App Bar.
- **Keyboard**: `⌘K` palette, `F` fit, `Shift+F` focus the selected Task, `I` Inspector, `↑` / `↓` (or `j` / `k`) move the List selection, `Esc` close overlay / menu / clear selection, `?` shortcut sheet. No write shortcuts exist.

**Excluded from V1 UI**: Task creation/import/cancel/finish/subtask/retry entry points, graph canvas mutation/workflow editors, Saved Views managers, a raw SSE event browser (the former Events tab), static login topology diagrams, and production-bundled demo fixtures or component galleries (keep fixtures/galleries test-only).

## 4. Verification

Before shipping a UI change:
1. Run the frontend typecheck, unit tests, and production build (`apps/web`), plus the Rust workspace checks (`hub` embeds `apps/web/dist`).
2. Inspect the running Web UI in both resolved appearances (light and dark, including System following the OS) at desktop widths, checking keyboard focus, truncation, and reduced motion.
3. Report automated tests and visual checks honestly as separate evidence.
